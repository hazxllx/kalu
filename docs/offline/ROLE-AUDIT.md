# Role-by-role offline mutation audit

This is an incremental audit, not a declaration that the system is offline-ready.
Only rows marked **handler: yes** may currently enter automatic synchronization.
The mutation tier describes the workflow policy; it does not grant permissions.
When the current UI has no audited handler, the action remains online-only even
if its eventual policy tier is `SAFE_SYNC` or `OFFLINE_DRAFT`.

## Progress

| Role / scope | Audit status | Offline implementation |
| --- | --- | --- |
| BHW | Audited below for household, intake, M1, guardian-link, notification, and own-profile mutation routes. | Household create, allow-listed factual update, and member measurements only. |

### BHW Household Profiling focused verification

Automated tests exercise encrypted outbox persistence across database close/open,
pending-edit overlay, one successful reconnect pass with the same idempotency key,
no second send after sync, conflict/revision behavior, the existing role allowlist,
and rejection when current role/barangay scope no longer authorizes the write.
The backend route uses current authentication and scope checks; the API remains
the final authority. These tests use fakes and do not replace live Supabase/RLS
verification in a dedicated development project.

RHU Personnel may cache and view authorized facility-bound intake,
consultation, health-service, and notification data where the existing
frontend supports it. Intake data capture is deliberately separated from
clinical processing: only a future draft handler may synchronize the former,
and no RHU clinical decision is automatically finalized offline.
